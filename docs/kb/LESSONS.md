# Lessons learned (UNIX Salla theme)

Every agent reads this before building or reviewing. Each lesson is a real bug or rework we already paid for, with the commit that fixed it. **When you fix a new bug, add a lesson here in the same commit.**

Format: what went wrong · the rule now · how to check · commit.

## Salla components and runtime
1. **A `salla-*` component hid its slot with a class the theme never styled.** `salla-add-product-button` wraps the slot in `<span class="s-hidden">` for `out-and-notify`. Our CSS had no `.s-hidden`, so «نفدت الكمية» showed twice. · Rule: when a component renders twice or shows something it shouldn't, inspect its light-DOM wrappers and check that the theme styles every `s-*` utility class it relies on. · Check: `grep -rn "s-hidden" src/assets/styles`. · 0c2f657
2. **`salla.lang` doesn't contain theme keys.** The size finder and card heart showed raw keys. · Rule: JS strings fall back to the bundled locale strings, not just `salla.lang.get`; hard-coded English in Raed JS (the toast's `aria-label="Close"`) gets a bundled feminine/neutral key (`blocks.unix.toast.close`) with an English fallback. · 8a9bc20, 6.1 review follow-up
3. **Salla's own labels are masculine.** The card add-to-cart used Salla's «أضف للسلة». · Rule: pass the theme's feminine `trans()` label into `salla-*` components wherever they accept a label or slot. · 46759ed
4. **Carousel navigation didn't attach when a tab rendered late.** · Rule: wait for `componentOnReady()` and retry once per instance; never assume a web component is upgraded at `DOMContentLoaded`. · ebc5464, bfa39b0
5. **Checkout button could stay locked.** Listeners were added on every render, and a failed request never released the lock. · Rule: register listeners once, release on `.catch`, add a timeout (15s), and release on `pageshow` (bfcache). · fc06a49, b058ba7
6. **Product card heart styled the outer host, not the real button.** · Rule: style and set `aria-pressed` on the inner `<button>` that receives focus, and revert the state if the API call fails. · e465d64
22. **Merchant text went into `innerHTML` unescaped.** The add-to-cart toast printed option names and values (`${opt.name}: ${opt.value}`), and the product card printed the name, subtitle, preorder label and promotion title raw, so a merchant-entered `<img onerror>` would run (Salla TECH 2.4). · Rule: every API string or URL interpolated into a JS template goes through the component's `escapeHTML()`, attributes included; only theme-owned strings and `salla.money()` output skip it. `escapeHTML` uses `String(str ?? '')` so a missing value prints nothing, not «null». Salla labels that come from the product (`add_to_cart_label`) are API data too. · Check: `grep -n '\${this.product\|\${opt' src/assets/js/partials/*.js` and confirm each hit is wrapped. · 6.1 KB audit (2026-11-09)
33. **Shopper-written text went out with `|raw`.** The order page printed the store/shipping rating comment `unix_rating.content|raw` (Raed-inherited), so markup a shopper typed would render. · Rule: `|raw` is only for merchant rich text we control the context of; shopper text is plain `{{ }}` or `|striptags|raw` when entities must still render. Every new `|raw` gets a row in SALLA-TWILIGHT R5. · Check: `grep -rn '|raw' src/views`. · 6.1 review follow-up (2026-11-09)
29. **A camelCase attribute on a `salla-*` component was silently ignored.** `profile.twig` had `dateFormat="Y-m-d"`; HTML lowercases it to `dateformat`, which Stencil doesn't map, so the birthday picker used its default format (Raed-inherited). · Rule: in Twig, `salla-*` props are always the kebab-case `attr` from `docs.json` (`date-format`). · Check: `grep -rnoE '<salla-[^>]*\s[a-z]+[A-Z][a-zA-Z]*=' src/views`. · 6.6 KB audit (2026-11-09)
30. **The documented `cart:submit.start/end` hooks were missing from `cart.twig`** (Raed omits them too), so apps that inject next to checkout had nowhere to render. · Rule: every hook in Salla's hooks list for a page exists in our template, even if Raed lacks it. · Check: `grep -rhoE "\{% hook '?[a-z:._-]+'? %\}" src/views | sort -u` against SALLA-TWILIGHT §hooks. · 6.6 KB audit (2026-11-09)
31. **We removed PDP social sharing for parity (D54) without checking Salla's review criteria,** which require direct link, X/Twitter and WhatsApp sharing (UX 4.1.12–13). · Rule: before removing a Raed feature, check `docs/kb/SALLA-TWILIGHT.md` review criteria; if Salla requires it, keep it behind a setting (default on) and record a D-number. When a Salla component depends on a third-party script (AddToAny here), plan for that script being blocked: a fallback (native share, copy link) or hide the control, never a dead button; and an early tap must wait for `customElements.whenDefined` (only on the component path; the fallback runs synchronously in the click so iOS keeps the user gesture). Only `AbortError` from `navigator.share` is a shopper cancel; anything else falls through to copying. Salla's app webview always takes the component path: with a slotted trigger that is `host.open()`, and each platform link then emits `share-element` for the app (not `mobile::share.open`, which only the component's own default button uses). Never hide a control the shopper just tapped (focus is on it): show an error and announce it in a `role="status"` region; hide only at load time. · D135, 6.6 KB audit (2026-11-09)

34. **A new textarea setting shipped with `maxLength: 20000`** (`unix_pdp_model_info`), copying the colour-links field, although Salla TECH 1.4 caps Twilight lengths at 1000 (SALLA-TWILIGHT R1). · Rule: every new `twilight.json` field has `maxLength` ≤ 1000; when one setting would need more, split it per model or per line. After any `twilight.json` edit, refresh the R1 line numbers. · Check: `grep -n '"maxLength": *[0-9]\{4,\}' twilight.json` lists only the known R1 fields. · 3.12 review (2026-11-10)
35. **Link-picker values went into `href` unchecked** (returns-policy line, size-help button), so a typed `javascript:` or `//other-host` value would render as a link. · Rule: a merchant link (variable-list `.url` or a typed string) is used only when it starts with `https://`, `http://` or a single `/`; anything else renders as plain text or no button. WhatsApp links are built only by `components/unix-whatsapp-url.twig` (digits only, no link under 8 digits). · Check: `grep -rn 'href="{{' src/views/components | grep -v 'url }}\|link('`. · 3.12 / 2.10 review (2026-11-10)
36. **The «تسوّقي الإطلالة» card sat over the bottom inline-end corner of a non-mirrored image,** so it covered a different part of the photo (and different hotspots) in AR and EN, and it painted above the hotspots. · Rule: anything pinned to a spot on an image that doesn't mirror keeps its physical corner in both languages (`inset-inline-*` in RTL, swapped under `[dir="ltr"]`), interactive markers stack above overlays (`isolation` + `z-index`), and positions are clamped so a 44px hit area is never clipped (DS §7, §8.54). · Check: open the section in AR and EN at 1280 and confirm the card covers the same corner and every hotspot is clickable. · 2.10 review (2026-11-10)

## Twig
7. **A nested Twig comment turned a usage example into a live self-include.** Twig comments don't nest; `{# … {# … #} … #}` closes early. · Rule: never put `{# #}` inside a comment. · Check: `pnpm twig:check`. · d9d4a01, 51f192e
8. **`|date` on a missing value crashed the JSON-LD.** · Rule: guard every optional field before a filter (`{% if x %}` or `|default('')`). · 4f111fd, d0246a1
9. **PHP-Twig arrow functions broke our checker, not Salla.** · Rule: keep `scripts/twig-check.mjs` in sync with what Salla's Twig supports. · 38dab65
10. **Empty editor fields rendered blank sections.** · Rule: an empty field shows the unix.sa default (D115); test every component with all fields empty. · cdcf732, 0530d70

## Parity with unix.sa
11. **We guessed sizes and ratios instead of measuring.** Card images, page edge, gaps and heading sizes were redone 3 times. · Rule: measure on live unix.sa (DevTools computed styles at 390px and 1440px) or read `reference/shopify-theme/` before building. Never eyeball. · 42c1b7a, c4b8052, 3286f4b
12. **A setting that looked like a theme bug was the demo store's setting.** Breadcrumbs showed because the demo store had them on; the code default was correct. · Rule: before "fixing" what you see in preview, check the editor settings on the demo store. · 3baa30c
13. **Editor section names didn't say which theme they belong to.** · Rule: every component title starts with «يونكس · » / "UNIX · ". · 3baa30c

## Copy and i18n
14. **Masculine Arabic slipped into dashboard labels.** · Rule: every Arabic string addresses the shopper in the feminine voice; reviewers grep new keys in `ar.json`. · b68e5c8, b8a7691
15. **Price row showed «0 ﷼».** · Rule: price, sale price and "from" rows are mutually exclusive, and a zero or missing value renders nothing. · e9ecaf9

## Accessibility
16. **Touch targets under 44px on cards and filters.** · Rule: 44×44px minimum hit area in AR and EN (D114). · ebb078c
17. **Sold-out state was shown with opacity and greyscale only.** Low contrast, and colour isn't enough. · Rule: sold-out uses `--c-text-muted` plus text («نفدت الكمية»), never opacity. · 35a6e31, 0c2f657
23. **Product card had two or three tab stops to the same URL, and the first was named by the merchant's image alt** («IMG_2041»). · Rule: one focusable link per card, named by the product name (the title link); the image link and the full-image overlay link are `tabindex="-1" aria-hidden="true"` (A11Y R17.1–17.2). **Never put content screen readers need inside an `aria-hidden` link:** the first fix left the sold-out/preorder/promotion badge inside it and hid «نفدت الكمية» (LESSONS 17); badges now follow `</a>` inside `.s-product-card-image`, with `pointer-events: none` set at the top level (`.s-product-card-entry :is(…)`) so it covers every card: UNIX rows, brand page, wishlist. Same rule in the add-to-cart toast (image link `tabindex=-1 aria-hidden`, `alt=""`). · Check: `grep -n 'href="\${' src/assets/js/partials/product-card.js` and confirm nothing but images sits inside the hidden link. · 6.1 KB audit (2026-11-09), badge fix in the review follow-up
24. **We claimed the announcement bar met WCAG 2.2.2 because it paused on hover and focus.** The Understanding doc says hover/focus-only pausing is not a mechanism. · Rule: anything that moves or auto-updates for more than 5s gets a visible pause/stop button (fixed name + `aria-pressed`, 44px hit area), and the pause holds until the shopper presses it again. Focus on the toggle itself must not count as a focus-pause (or play does nothing until focus leaves), and an expanded hit area is centred so it doesn't steal the neighbour's edge. · Check: `grep -rn "setTimeout\|setInterval" src/assets/js/partials` and confirm each rotating UI has a toggle. · 6.3 KB audit (2026-11-09)
25. **Raed's `.btn--collapse` (PDP add note / upload file) never exposed its state, and the closed panel's textarea stayed a hidden tab stop** (opacity 0 only). · Rule: every disclosure trigger gets `aria-expanded` + `aria-controls` kept in sync by the JS, and a collapsed panel is `visibility: hidden` (or `hidden`/`inert`), never just transparent. · Check: `grep -rn "btn--collapse\|data-show=" src/views`. · 6.3 KB audit (2026-11-09)
26. **Tabbing backwards could put the focused element under the fixed header or the mobile sticky add-to-cart bar** (WCAG 2.4.11). · Rule: `html` carries `scroll-padding-block-start: var(--header-h)` and, on the PDP below 576, `scroll-padding-block-end: var(--sticky-atc-h)`; any new fixed bar adds its height there. · Check: `grep -rn "scroll-padding" src/assets/styles`. · 6.3 KB audit (2026-11-09)
32. **A merchant `<h1>` inside the product, category or brand description gave the page a second h1.** Pages and articles already demoted it; the PDP, PLP banner, brand page, FAQ answers (`row.html`) and thank-you order instructions didn't. · Rule: every merchant rich-text output (`|raw`) that sits under our page h1 gets the same plain `replace({'<h1': '<h2', '<H1': '<h2', '</h1>': '</h2>', '</H1>': '</h2>'})`; no HTML parsing in Twig. · Check: `grep -rn '|raw' src/views` and confirm each description/body hit has the replace. · 6.3 KB audit (2026-11-09)

## Performance
18. **The LCP image path pointed to a size Salla's CDN didn't serve well.** · Rule: images go through `|cdn(width)` with a real `srcset`; preconnects come before stylesheets in `master.twig`. · 27abcc0
27. **Two home sections still printed raw merchant image URLs** (`unix-collection-overlay`, `unix-featured-products`), so phones downloaded the full upload. · Rule: no `src="{{ url }}"` for a merchant or product image; always `|cdn(width)` with `srcset`/`sizes` matching the CSS width, and guard empty or object values first (`|default('')|trim`, `is iterable`). When JS swaps `src` later, remove `srcset` first, and normalise a field once (when the data is built) so every use reads the same value. JS can't rebuild `|cdn(width)` URLs (scheme undocumented); hydrated images use Salla's `thumbnail` where small. Raed's brand logo was raw too (now cdn 160/320). A second sweep found five more raw URLs (collections grid, home blog, article card, article hero, cart line image), all fixed; run the grep over all of `src/views`, not just the files the audit named. · Check: `grep -rnE 'src="\{\{ ?[a-z_.]+ ?\}\}"' src/views`. · 6.2 KB audit (2026-11-09)
28. **The hero `<video>` had no `poster`.** · Rule: a video gets the fallback image as `poster` from JS (`video.poster = img.currentSrc`), the file the browser already picked from the srcset. Never a fixed `poster="…|cdn(w)"` in Twig: it can differ from the chosen candidate and download twice (first fix did this; reverted in review). · Check: `grep -rn '<video' -A8 src/views | grep poster`. · 6.2 KB audit (2026-11-09)
19. **Preview images hot-linked from places Salla's reviewers can't load.** · Rule: images in `twilight.json` previews use the jsDelivr `@main/public/images/previews/` path. · fc06a49

## React (salla-next / twilight-components-react)
39. **The buy-now button was squeezed into the add-to-cart cell, and the first CSS fix stopped the buttons from hydrating.** `twilight-components-react` wraps each web component in a class-less `HydrationBoundary` <div>, so flex rules written for the host as a direct child no longer applied. `display: contents` on that div fixed the layout but removed its box, and `useInView` never fired, so `salla-add-product-button` never hydrated. · Rule: never drop the box of a HydrationBoundary div while it waits. Target it only after hydration (`> div:not([class]):not([style*='width'])`, since it carries `style="width:100%"` until then), and after any layout change around a `salla-*` component, check in a browser that the component hydrated (puppeteer `waitForSelector('… salla-button')`), not only that the layout looks right. Screenshot a product that is **in stock**: an out-of-stock one hides the buy row. · ~/unix `unix-pdp-buy.scss` (2026-11-13)
40. **A preload made inside a lazy route lands after the inline critical CSS.** React 19 writes `ReactDOM.preload(…, { fetchPriority: 'high' })` at the top of `<head>` only when it is called during the shell render. The home and PLP routes render lazily, so their LCP preloads came after 140-190 KB of inline `<style>`, and a rendered `<link rel=preload>` went to the same place. · Rule: issue LCP preloads from the root component using the matched routes' `loaderData` (`app/lib/lcpPreload.ts`), and build every URL from the same constants the `<img>` uses, so nothing downloads twice. Check the byte offset of `as="image"` against the first `<style` in the HTML. · ~/unix 0528b2f
41. **One Salla web component that changes its own light DOM made React re-render the whole PDP.** `salla-installment` and `salla-social-share` change their children before hydration (#418). With no Suspense boundary, React throws away the server tree up to the route, which costs about 1 s of mobile CPU plus layout shift. · Rule: wrap every `salla-*` element with children or slots in `<HydrationIsland>` (a Suspense boundary). Check the production build for `#418` in the console, and in dev check that SSR nodes such as `h1` and `footer` keep their identity after hydration. · ~/unix 0528b2f
42. **Critical CSS for a route must also style its pending skeleton.** The PLP skeleton cards had no height in the first paint (their rules lived in `unix-products-tabs.scss`), so the footer rose into view and jumped when the streamed list arrived: desktop CLS 0.33. · Rule: a critical sheet includes the rules for everything painted before the streamed content arrives, skeletons included. Check CLS sources with a PerformanceObserver (`previousRect` vs `currentRect`), not only the final layout. · ~/unix 0528b2f
43. **The header cart icon opened /cart instead of the drawer.** The engine's document-level SPA link handler turned the click into a router navigation before the listener on `salla-cart-summary` could cancel it. · Rule: a click that must override an engine link uses a window capture-phase listener scoped with `host.contains(event.target)`. Test the real click in the production build, not only the unit test. A lazily loaded dialog records its opener at open time, because the page is already `inert` by the time it mounts. · ~/unix 0528b2f
44. **The add-to-cart spinner never stopped on the live preview, although the item was added (cart badge 7 → 8).** `UnixBuyForm` subscribed through `window.salla.cart.event.onItemAdded` in a mount effect; at hydration that object can be missing, so nothing subscribed and only the 8 s safety net remained. Salla's own `.s-button-loader` also drew a second spinner over ours on a dimmed button. Fix: bind `cart::item.added` / `cart::item.added.failed` on `window.salla.event` with a `theme::ready` retry (same pattern as `CartDrawerHost`), and hide `.s-button-loader` + keep `opacity: 1` in the `unix-button-loading` mixin. Rule: never subscribe to a Salla sub-object at mount; bind on the bus with a ready retry. Source: https://docs.salla.dev/422610m0 (Twilight events).
45. **«كمّلي الطقم» always answered «تعذّرت الإضافة», with no network request.** `CartPair` took `const addItem = window.salla.cart.addItem` and called it unbound; the SDK method reads `this`, so it threw before the request. Unit tests mocked `addItem` as a plain function and passed. · Rule: call SDK methods on their object (`cart.addItem(payload)`), never through a detached reference; a new cart action is proven in the browser (Network tab), not only in unit tests. · cacebfb
46. **A set («مجموعة منتجات») in the cart is not shaped like a product.** Found in the mobile walkthrough: (a) `updateItem({id, quantity})` on a product with a required option answers 422 «خيارات المنتج مطلوبة»: send the line's chosen options again (`lineOptionsPayload`); a set updates without them. (b) A set line's `options` is `[]`; its pieces and chosen sizes come only with the `bundle` include (`cart.api.details(null, ['options', 'bundle'])`), and the engine's `cart/{id}` read has none. (c) A set's `original_price` is the line total (716 for two sets of 358), while a product's is per unit. (d) `:has()` can't be nested inside `:has()`: the rule is dropped silently. · Rule: test every cart change with a product with sizes and with a set, at quantity 2. · cacebfb, d0ebcdb
47. **A `<Salla…>` wrapper placed where nobody scrolls never loads.** The search modal moved under the footer (publish review), where `<SallaSearch>` (not `eventTriggered` in `withDeferredHydration`) waits for its skeleton to come into view: the header icon dispatched `search::open` to nothing until the visitor reached the end of the page. · Rule: a component opened by an event and mounted off-screen uses its `…Core` export; after moving a component, tap its trigger on a fresh page load. · 862f5dc
48. **`display: none` on a deferred `<Salla…>` component keeps it from ever loading.** The card hid the quick-add box until its button had an icon (`:not(:has(… i)) { display: none }`); the button mounts when its skeleton is in view, and a box that isn't rendered is never in view, so listing pages had no quick add on phones. · Rule: hide a deferred component's box with `visibility`, never `display: none`; check quick add on the listing page, not only on the home sliders. · (same commit as D147)
49. **Salla's physical `top` on a popover beats a logical end inset.** The share popover had to open above its button (under it, it covered the footer on phones). `inset-block-end: 100%` alone did nothing: `.s-social-share-list` keeps Salla's own physical `top`, so the box stayed pinned under the button. · Rule: when moving a `salla-*` popover to the other side, write the shorthand with `auto` on the old edge (`inset-block: auto 100%`), then check it in the browser. · ef281ff
50. **Rich-text lists had no bullets although `ul { list-style: disc }` was set.** The base theme resets `li` itself to `list-style: none`, and `list-style` on the `ul` only reaches the items by inheritance, which that reset blocks. · Rule: in every rich-text scope restore the marker on the item (`ul > li { list-style: disc }`, `ol > li { list-style: decimal }`), and look at a description with a real list. · ef281ff
51. **The browser's own (English) validation bubble showed on an Arabic page when no size was chosen.** `invalid` does not bubble, so a normal listener on the form never ran; a capture listener does, and calling `preventDefault()` on the event is all that removes the bubble. The default focus move goes with it, so focus the field yourself and say the message in a `role="alert"` line. Salla's own validation keeps working. · Rule: listen for `invalid` in the capture phase, cancel it, and show the theme's translated message. · ef281ff
52. **The card bag added size XS without asking.** Salla's card quick-add API (`cart/{id}/item/{id}/quick-add`) picks the first value of a required option itself, and `salla-add-product-button` on a card has no `salla-product-options` to validate. · Rule: a product with options (`has_options`) or a set (`group_products`) must never use quick add; its bag is a link to the product page (`quickAddNeedsOptions`). · ef281ff
53. **An empty home block left a ~300px band.** The engine writes each block's `height` reserve as an inline `min-height` on the wrapper until the block mounts, and `height` is one fixed string per block, so the blog block reserved its height even with no article picked and then rendered nothing. Only an `!important` rule beats an inline style. · Rule: a block that can render nothing gets a class from its `className` function in `app/router.tsx` when it has nothing to show, styled `min-block-size: 0 !important` in its own scss (`.s-block--unix-blog-empty`). · D149 batch
54. **A deferred `<Salla…>` component inside engine markup showed a grey card that never filled.** On the cart page the engine's `CartSummary` ends with `SallaTieredOffer`; until it is near the screen it draws Salla's ~100px skeleton card, and a store with no tiered offer then loads an empty 0px element, so a still page shows a grey box and a scrolling one jumps. Hiding the skeleton (not the wrapper) keeps the component loading (lesson 48); the 0px wrapper still takes a flex gap. · Rule: hide only the `.s-skeleton-*` child, never the deferred wrapper, and recheck the selector on every engine update. · D154 batch
55. **«Has an instalment provider» is not «offers Tabby or Tamara».** `store.settings.installments` is a keyed object (`tabby`, `tamara`, `spotii`, `mispay`, `emkan`, `madfu`, `mokafaa_alrajhi`) whose values can be false, or a list, or a string. `Object.keys(x).length > 0` called `{ tabby: false }` a provider, and any provider unlocked copy that names Tabby and Tamara (perk, FAQ, FAQPage JSON-LD). · Rule: gate Salla's own widget on `hasInstallmentProvider` (any truthy value), and gate copy that names a brand on `offersTabbyOrTamara`; read it through `storeInstallments(store)` everywhere. · D153/D155 batch
56. **A second buy form in the page would have bought the wrong thing.** Salla's `salla-add-product-button` reads the FIRST `form.product-form` in the document for buy now (`document.querySelector('form.product-form')`) and gives Apple Pay `form-selector: "form.product-form"` (twilight-components `salla-add-product-button2.js`), and `product::price.updated` / `…failed` / `product:options.updated` carry no product id, so the engine `useProduct` takes every one. A quick-view sheet portalled at the end of `<body>` on a product page would have sent the page's options with the sheet's product id, and its prices would have landed on the page. · Rule: a second product form goes in a root BEFORE `.app-inner` (it is first while open, gone when closed), borrows `page.id` (never on the cart page, where it is the cart id) and gives it back only if still on the same path and nobody set another id since (the form unmounts after the exit animation, after a navigation has set the next page's id); the page stays `inert` and every product-state listener keeps ignoring events (`useLiveProduct` `ignore`) until the sheet's FORM unmounts, not until it is marked closed; then re-price the page form. Test buy now from the sheet on a product page in the browser, not only on the home page. · D158
57. **The size finder showed nothing on a set, and selecting through the DOM would not have stuck.** `UnixSizeFinder` built its pieces from `product.options` (empty on a «مجموعة منتجات» set) and looked for `options[<id>]` inputs, but the set's size radios are `UnixSetPicker`'s, named `bundle[s][i][options][id]` and **React-controlled** from `UnixBuyForm` state: checking one and dispatching `change` (the `salla-product-options` path) is undone by the next render, and a state update fires no `change`, so the form's `getPrice` never ran. · Rule: a feature that selects a value in a React-controlled control goes through the owner's state (`UnixSetSizeFinder` → `onFinderSelect`, marks as props), keeps her own tap on a separate path (`touchedRef`), and calls `salla.product.getPrice(new FormData(form))` itself in an effect after the selection commits when `productFormComplete(form)`. Test it on a set at the PDP and in the quick-view sheet. · dcc86dc
58. **Salla's Apple Pay button for a cart would have paid for the product on the page.** `<salla-quick-buy apple-pay-only cart-id>` is the cart mode (`resolveCheckoutType()` → `mini_checkout` only while `productId` is empty), but its init fills an empty `productId` from `page.id` behind `salla.url?.is_page`, which is the function itself and always truthy.
